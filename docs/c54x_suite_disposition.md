# C54x suite disposition

The authoritative disposition table is in
[c54x_section_trial.md](c54x_section_trial.md). It records each replacement's
retained contracts, deliberate coverage reductions and validation limits.
The former reduction-order table and frozen profile review manifests described
deleted phase-chain sources and are retired, not current coverage obligations.

Section names/counts live in `fixtures/c54x_sections.json`; the catalogue is
registration metadata, not proof of correctness. Generic CPU and copied-firmware
scopes remain separate. See [tests/README.md](../tests/README.md) for commands.

The [frontend retirement inventory](c54x_frontend_retirement.md) classifies the
atomic migration surface. It does not authorize deletion of independent
assertions or establish staged parity.

The integration checkpoint passes all 518 registered sections, linked firmware
context/cold controls, the full host suite and seven affected handset gates.
The canonical disposition records exact counts, source identity, timings and
remaining hardware/coverage limitations. Later selected runs do not renew the
complete regression or unrelated handset workflows.
